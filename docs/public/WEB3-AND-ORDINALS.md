# Web3 & Ordinals / Web3 与 Ordinals

## English — Primary

Fractal Legend is designed to explore verified digital ownership in a game with server-owned rules. No production Ordinals integration is live.

### Planned activation path

**Ordinals Asset → Ownership Verification → Metadata Verification → Game Mapping → Activation Requirements → Activated Game Asset**

Each step is intended to fail closed. Owning an on-chain object would not let a client invent stats, bypass progression, or select an unsupported mapping.

### Intended asset categories

Weapon, armor, accessory, item, skin, identity, badge, and a possible future pet are **PLANNED** categories. Their schemas, balance rules, and release order are not finalized.

### Ownership is not unlimited power

On-chain rarity does not automatically equal unlimited in-game power. Every activated asset remains subject to game balance, eligibility, activation rules, progression requirements, server validation, and versioned mappings.

The intended value of Ordinals is ownership, identity, collectibility, provenance, appearance, eligibility, and social status.

### Ordinals skins

An on-chain image is not intended to become a complete battle sprite directly. A future Ordinal may establish ownership, identity, theme, or eligibility; a reviewed game art template would provide animation, collision, readability, and runtime presentation.

### Security boundary

Future integration must separate wallet proof, indexer data, metadata validation, game mapping, activation, and runtime authority. Private keys, mnemonic phrases, hot-wallet credentials, and unrestricted client-authored attributes must never enter public project artifacts or ordinary gameplay messages.

### Current status

- Wallet connection: **PLANNED**
- Fractal / Bitcoin deposit: **NOT LIVE**
- Withdrawal: **NOT LIVE**
- Indexer, confirmation and reorg handling: **PLANNED**
- Ordinals metadata verification: **PLANNED**
- Game activation and rendering: **PLANNED**
